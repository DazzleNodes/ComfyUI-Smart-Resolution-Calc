# Vault Specification (vault-spec)

The constitution for project knowledge vaults: the **one canonical definition** of what a vault is, how it is laid out, who may write what, and how the surrounding skills, agents, and tools relate. Everything else — skills, agents, tools, per-vault docs — **cites this file instead of restating it**.

**Four audiences, one text.** (1) Humans, as reference. (2) Claude sessions and agents, as a briefing — an agent told "score vaults against this spec" needs no other layout education. (3) Skills, which cite sections (`vault-spec §WL`) instead of carrying copies. (4) Tools, which implement clauses and cite them in code comments and test names, so drift between law and enforcement is greppable from either side.

**Scope rule for this document:** it defines *what*; skills define *how*; tools *enforce*. A sentence explaining procedure belongs in a skill. A project-specific fact belongs in that vault's own bylaws (§DIST). Provenance: every normative rule here was field-earned during the 2026-08 vault-bootstrapping arc, not invented up front.

---

## §LAYOUT — What a vault is

A **vault** is the directory `private/claude/` inside a project's `private/` folder, treated as an Obsidian-style knowledge base.

```
<project>/private/              <- its OWN git repo (dz private-init); typically NO remote:
│                                  disk backup is the only backup. Invisible to the parent
│                                  repo (/private/ gitignored there).
├── CLAUDE.md                   <- orientation for sessions working here (bylaws pointer)
└── claude/                     <- THE VAULT
    ├── *.md                    <- flat pool of timestamped docs (the knowledge)
    ├── _maps/                  <- Maps of Content (hand-maintained navigation)
    ├── _oracle/                <- the oracle's index: manifest.md, concepts.md,
    │                              backlinks.md (generated), observed-gaps.md (§GAPS),
    │                              plus dated oracle outputs
    ├── _todo/OPEN-LOOPS.md     <- the deferred-work dashboard (commitment surface)
    └── support dirs as needed  <- issues/, commits/, releases/, notes/<area>/,
                                   drafts/, checklists/, questions/, instructions/, ...
```

**LAYOUT-1 (the floor).** Minimum viable vault: `private/claude/` + `_maps/` + one MOC file with `type: moc` frontmatter. Below this floor the oracle has nothing to traverse.

**LAYOUT-2.** `private/` SHOULD be its own git repo (`dz private-init`). An unversioned vault has no history — a bigger loss risk than an unmapped one.

**LAYOUT-3 (topology).** Exactly one **canonical** `private/` per project. Every git worktree reaches it by junction (Windows) or symlink (POSIX). Any other real `private/` directory is a **stray** — it silently forks the knowledge graph and must be consolidated (a stray hid 4 docs + 132 files for months in one project).

**LAYOUT-4.** `backlinks.md` is **generated only** — regenerated by `generate-backlinks.py`, never hand-edited.

## §LADDER — Maturity, not compliance

A vault is scored by **level** plus **orthogonal axes** — "where is it on the ladder," never "is it compliant."

| Level | Has | Unlocks |
|---|---|---|
| **L0** | docs only | nothing — reachable only by filename |
| **L1** | + `_maps/` MOC | oracle can traverse |
| **L2** | + `_oracle/` manifest, concepts, backlinks | oracle skips full scans (the RAG-lite index) |
| **L3** | + `_todo/OPEN-LOOPS.md` | deferred work has a surface |
| **L4** | + `observed-gaps` loop, drift guards | self-maintaining |

**Orthogonal axes** (independent of level): **versioned?** (LAYOUT-2) · **topology** (canonical / linked / stray / backup-copy) · **link health** (`vault-lint --check`) · **freshness** (MOC `last_refreshed` vs newest doc / repo HEAD).

**LADDER-1.** Backup-copy vaults (name-pattern or user-confirmed) are scored but never modified, and never counted as unmapped debt.

## §NAME — Naming conventions (the producer interface)

This is the **entire contract ring-1 producers pay** (§ECO): a document becomes oracle-legible through its filename and landing spot alone. Zero further ceremony — by design, because producers (`/dev-workflow-process`, `/postmortem*`) are the highest-traffic commands in real sessions.

Standard shape: `YYYY-MM-DD__HH-MM-SS__<type-marker>__<topic>.md` (timestamp from `date`, never guessed).

| Type marker | Document |
|---|---|
| `dev-workflow-process` | DWP design analysis |
| `full-postmortem` / `context-postmortem` / `mini-postmortem` | postmortems |
| `claude-plan` | preserved plan-mode output |
| `whereweare` | forward-looking session snapshot (no topic slug) |
| `investigation` | gap/audit investigation |
| `HANDOFF-<target>` | cross-box handoff document |
| `idea` / `lesson` (older form: `idea_<topic>`) | short-form notes |
| `notes/<area>/...__<who>_<topic>` | notes; `<who>` ∈ both/claude/user |
| `issues/issue_<N>_YYYY.MM.DD_NN` | posted issue-comment archive |
| `issues/issue_new_<slug>`, `new_bug_*`, `new_epic_*` | drafted issue bodies |
| `issues/issue_<N>_..._00_pre-refresh-body` | archived live body before an edit (§AUTH-6) |
| `commits/commit_*` | staged commit messages |

**NAME-1 (extension point).** Projects MAY add local types following the same shape. Local types are documented in the vault's MOC under "Naming conventions in use" — the vault's bylaws (§DIST). Examples in the wild: `DISCUSS_RndN_*` (dazzlecmd), `HANDOFF-*` originated as a session-logger bylaw.

## §WL — Wikilink rules

Links resolve by **vault-root path or bare filename** — the resolution model `generate-backlinks.py` implements.

- **WL-1** `[[_todo/OPEN-LOOPS]]` and `[[2026-08-13__00-21-02__whereweare]]` resolve. `[[../anything]]` NEVER resolves — no `../` traversal exists.
- **WL-2** No `.md` suffix inside a target (the parser keeps it, breaking resolution).
- **WL-3** No `[[#Heading]]` anchors — they do not resolve through the backlinks tooling.
- **WL-4** Inside markdown tables use alias-free `[[target]]` — a `\|` alias escape is read as part of the target and reports broken.
- **WL-5** Link only targets that exist on disk (issue stubs are created to satisfy this, not dangling links).
- **WL-6** Aliases elsewhere are encouraged for readability: `[[long-timestamp-name|Short label]]`.

Enforcement: `vault-lint.py` (checks all; fixes only the provably-unique class), `generate-backlinks.py --broken`. On Windows consoles both need `PYTHONIOENCODING=utf-8` (cp1252 dies on non-ASCII).

## §AUTH — Write authority

The trust gradient in one table. "Structural" = bulk rewrite of navigation/status surfaces; "additive" = appending or linking without altering existing content.

| Surface | May create | May append/add | May rewrite | Notes |
|---|---|---|---|---|
| Doc bodies (dated docs) | authoring session | frontmatter, `## Related`, addenda — anyone | **NEVER** | corrections are visible notes, not silent rewrites |
| MOC, manifest, concepts | `/obsidian-init` | oracle (additive indexing: new-doc wikilinks, manifest status) | `/obsidian-update` under §AUTH-6 | oracle delegates structural staleness to update — it invokes the skill, never re-defines the procedure |
| `backlinks.md` | tool | — | — | generated only (LAYOUT-4) |
| `observed-gaps.md` | init template | oracle agent, skills, sessions (append-only) | status/seen fields only | §GAPS |
| `OPEN-LOOPS.md` | init | skills | update | promotion INTO it from observed-gaps is human-gated |
| `private/CLAUDE.md` | init | maintaining session | maintaining session | scope rule: only what a session needs before it would know to look at the vault; pointers, never copies |

- **AUTH-1** Uncertain inferences NEVER enter the map. If a connection is inferred rather than verified, it goes to `observed-gaps` with a refute-path; verification promotes it. (Provenance: an unverified commit↔issue inference propagated to five documents before review caught it.)
- **AUTH-2** **No background autofix, ever.** Prevention gates (§ECO gates) are the sanctioned "background" — they check and fail; they never rewrite.
- **AUTH-3** Mechanical link fixes (`vault-lint --fix`) touch only targets resolving to **exactly one** existing file; ambiguous or missing → report, never touch.
- **AUTH-4** Agents surveying vaults they don't own: read-only, absolutely (§SURVEY).
- **AUTH-5** Deletions in a vault go through `dz safedel` (recoverable), never raw `rm`.
- **AUTH-6 (checkpoint rule)** Before bulk-rewriting any planning/status document (MOC, PLAN, OPEN-LOOPS, a roadmap issue body): commit its current state first; for a live GitHub body, archive it to `issues/..._00_pre-refresh-body.md`. Every refresh is a tracked diff — the pre-edit state records what the team *believed*.
- **AUTH-7** File moves within a vault use same-volume `os.rename` (preserves ctime); collision = abort.

## §GAPS — The observed-gaps sensor log

`_oracle/observed-gaps.md`: what traversal *noticed*, typed as **observations, not objective facts** — the oracle infers; it rarely has ground truth.

Entry fields: `date · observer (agent/skill/session) · observation · evidence (citation) · confidence (low/med/high) · what-would-confirm-or-refute · status · seen: Nx`

- **GAPS-1** Body is append-only; only `status` and `seen` mutate.
- **GAPS-2** Status lifecycle: `open → promoted` (becomes an OPEN-LOOPS row; human-gated) | `dismissed` (reason required, **entry persists** — so non-gaps are never re-litigated) | `stale`.
- **GAPS-3** A recurring observation increments `seen` rather than duplicating — recurrence across independent traversals is evidence.
- **GAPS-4** An entry without a refute-path is a feeling, not an observation; it does not qualify for promotion.
- Triage lives in `/obsidian-update`; the file is a sensor log, never a work queue.

## §ECO — The ecosystem: three rings around the oracle

```
RING 1 — PRODUCERS (daily traffic; zero ceremony; never to be minimized)
  /dev-workflow-process, /postmortem*      write BY and FOR the main session;
                                           the vault ingests them by AWARENESS (§NAME)
  /obsidian                                the IN-door: signals planted intentionally
                                           FOR the oracle — the high-salience channel
  /whereweare, /investigate, plan-mode     land on convention alone

RING 2 — ORGANIZERS (occasional; absorb ALL integration debt)
  /obsidian-init      bootstrap: state machine, consolidation, structure, gates
  /obsidian-update    reconcile: discovery -> propose-block -> edits -> gates;
                      triages observed-gaps; owns structural rewrites (§AUTH-6)
  vault-lint.py       measure + mechanically fix the safe class (tool)
  generate-backlinks.py  derive the reverse-link index (tool)
  gates               pre-commit --check (opt-in), drift-guard tests

RING 3 — THE ORACLE INTERFACE (read constantly; the point of it all)
  /oracle (skill)     the OUT-door and the one-stop "I know nothing, let me query
                      and interact": answers, orientation, routing (the AGGREGATOR);
                      additive indexing inline, structural staleness DELEGATED to
                      /obsidian-update, inferences to observed-gaps (§AUTH-1)
  oracle agent        deep traversal in isolated context; how every other session
                      probes the whole vault
```

- **ECO-1 (frictionlessness).** Ring 1 pays zero integration ceremony (§NAME is the whole contract). Any design asking the highest-traffic commands to adopt write-time ceremony is wrong by construction.
- **ECO-2 (audience).** DWPs/postmortems serve the main session's own flow; the vault is their *secondary* beneficiary via awareness. `/obsidian` notes invert this — their primary audience IS the vault/oracle. One channel per intent.
- **ECO-3 (aggregator).** `/oracle` is the front door for the uninitiated: it remembers (renders this registry) and coordinates (probes vault state, proposes the right member with reasons — the last-mile shape). Members stay independently invocable.
- **ECO-4 (cap rule).** A new `/obsidian-*` leaf skill requires a written entry naming why the capability cannot live in an existing member. "Where do I start?" is answered by `/oracle`, never by a new skill.
- **ECO-5 (placement heuristic).** Deterministic + testable → tool (repokit-common). Judgment or user gates → skill. Big read fan-out → agent. Must-happen-when-forgotten → gate. Definitional → this spec. A component needing two of these is two components.
- **ECO-6 (planned member).** `obsidian-fleet` agent: cross-vault survey, briefed BY this spec, scored against §LADDER, bound by §SURVEY. Until built, ad-hoc surveys follow the same rules.

## §SURVEY — Guardrails for anything that crawls vaults

- **SURVEY-1** Dedupe by **resolved path** — worktree links make one vault appear several times (a real count dropped 111 → 105 on dedupe).
- **SURVEY-2** **Never execute git commands inside a discovered directory.** A `.git` *file* may be a gitdir pointer **aliasing a live worktree** — git run there operates on real state. Classify `.git` file-vs-directory by reading, not by running.
- **SURVEY-3** Read-only, absolutely. Survey output is a report; fixing is a per-vault, user-present activity (`/obsidian-init`, `/obsidian-update`).
- **SURVEY-4** Backup detection by name pattern is a **heuristic** — label it unverified; misclassifying a live vault as a backup buries it.

## §DIST — Distribution, specialization, evolution

**One spec, here, in git-repokit-common.** Projects receive it by **subtree pull** (a *maintained* copy — updates with every pull) or read the canonical checkout directly (the dazzlecmd pattern — equally legitimate; fixes reach consumers instantly). The subtree **mount point varies by project** (`scripts-repo/`, `scripts/repokit-common/`, others) — cite this file by name, never by a hard-coded prefix.

- **DIST-1 (no generated copies).** Vaults get a **versioned pointer** (`bootstrapped against spec v1.0.0`, written by init into `private/CLAUDE.md`), never an embedded copy. A generated copy is orphaned at birth — correct on day one, maintained by nobody, trusted because it looks authoritative. (Provenance: two generated CLAUDE.md files rotted for six months exactly this way.)
- **DIST-2 (invariants vs extension points).** Clauses stating tooling facts (§WL resolution, `_oracle/` contracts, §LAYOUT floor) are invariants — divergence just breaks the tools. Clauses marked as extension points (NAME-1) *expect* specialization.
- **DIST-3 (bylaws).** Per-project specialization lives in the vault's own maintained documents — the MOC's "Naming conventions in use" and `private/CLAUDE.md`. Local content in local files is healthy.
- **DIST-4 (no local forks of shared files).** Customizing a shared subtree file creates permanent merge debt (provenance: the `extra-targets` fork of `sync-versions.py` — safe today, guaranteed conflict tomorrow, feature invisible to every other consumer). Extend in bylaws; upstream what's general.
- **DIST-5 (graduation).** A bylaw proving general across projects graduates INTO this spec by normal commit — the same one-offs → scripts → source path used for code. Multiple vaults independently inventing the same convention is the promotion signal.

## §AMEND — Changing this spec

- **AMEND-1** Amendments record **adopted practice**, not aspiration — a rule enters after it has been exercised in a real vault, ideally after it has drawn blood.
- **AMEND-2** The checkpoint rule (§AUTH-6) applies to this file.
- **AMEND-3** Bump `spec-version` (semver: clause additions = minor; contract changes = major; wording = patch). Tools and tests cite clause codes (`§WL-4`), so renumbering is a breaking change.
- **AMEND-4 (the churn smell).** If this file changes often, something is wrong: procedure leaking in (belongs in skills), project-specifics leaking in (belong in bylaws), or the practice isn't stable enough to be law yet.
