# Human Test Checklist: hook stubs, gated branches, plain/rich output

**Target version:** 0.3.1
**Ships with commit:** TBD (v0.3.1: hook stubs and hooks/lib.sh, strict-branches, output markers, small fixes)
**Companion automated tests:** 145 in the suite. The new ones: `tests/test_install_hooks.py` (fresh-consumer install, stubs, worktree, missing copy, override, stamped branch list, flat mount), `tests/test_pre_push_hook.py` (gated branches, output modes, nothing-to-push), `tests/test_pre_commit_hook.py` (private branch names, first commit on a new branch), `tests/test_sync_versions.py` (broken table)

## What this is

A short list, deliberately. The automated tests install the hooks into fresh projects and commit and push through them. They capture the output, so they only ever see the plain markers. This list covers what capture cannot show: how the hooks look in your real consoles, and one install done by hand. About 15 minutes.

## Prerequisites

Everything happens in a scratch folder built by `tests/checklists/v0.3.0__scratch.py`, which vendors this checkout into a fresh project. Git calls carry `-C proj`, signing off (`-c commit.gpgsign=false`), an identity (`-c user.email=t@example.invalid -c user.name=t`) and `-c core.hooksPath=proj/.git/hooks`. Never change global git config, and never run these steps in a real repository. Use a new folder name each run.

**cmd.exe**
```cmd
python C:\code\git-repokit-common\tests\checklists\v0.3.0__scratch.py init %TEMP%\rk-v031
cd /d %TEMP%\rk-v031
```
**PowerShell**
```powershell
python C:\code\git-repokit-common\tests\checklists\v0.3.0__scratch.py init "$env:TEMP\rk-v031"
Set-Location "$env:TEMP\rk-v031"
```
**POSIX**
```bash
python /c/code/git-repokit-common/tests/checklists/v0.3.0__scratch.py init /tmp/rk-v031
cd /tmp/rk-v031
```

From here the `python rk.py ...` and `git ...` lines are the same in every shell. `python rk.py reset` returns to the seed commit.

For a commit you watch live, the steps below use this command, called **G-COMMIT**:

```
git -C proj -c user.email=t@example.invalid -c user.name=t -c commit.gpgsign=false -c core.hooksPath=proj/.git/hooks commit -m check
```

## High-Value Verification (~10 minutes)

### HV.1 -- The installer writes stubs, and its summary reads right
- [ ] **Steps:** `python rk.py install`, then open `proj/.git/hooks/pre-commit` (`type`, `Get-Content` or `cat`).
- [ ] **Expected:** the file is a short stub, starting "repokit-common hook stub", naming `REPOKIT_HOOK='pre-commit'` and `REPOKIT_INSTALLED_STRICT='main master staging live'`. The project's own pre-commit is kept as `pre-commit.backup-<stamp>`. The summary says the hooks run the vendored copy and need no re-install for a release, and lists the gated branches.
- [ ] **Why:** this is the new install mechanism; if the summary misleads, consumers will re-install or edit by hand.

### HV.2 -- Rich output in your terminals
- [ ] **Steps:** `python rk.py put private-prefix` and `python rk.py put cfg-private`, then `git -C proj add -f drafts/idea.md`, then G-COMMIT. Do this once in each console you use: **cmd.exe**, **PowerShell 7**, **Windows Terminal / Git Bash**. Afterwards: `git -C proj reset -q`.
- [ ] **Expected:** a blocked commit shown with `✗` (or a readable fallback), in colour, naming `drafts/idea.md`. Note any console where the symbols show as boxes or `?`.
- [ ] **Why:** the tests only see captured (plain) output; only a person can see what the terminal draws.

### HV.3 -- The plain fallback
- [ ] **Steps:** in a console from HV.2 that drew the symbols badly, set `REPOKIT_OUTPUT=plain` (cmd: `set REPOKIT_OUTPUT=plain`; PowerShell: `$env:REPOKIT_OUTPUT = "plain"`; POSIX: `export REPOKIT_OUTPUT=plain`) and repeat HV.2's commit. Unset it afterwards (cmd: `set REPOKIT_OUTPUT=`; PowerShell: `Remove-Item Env:\REPOKIT_OUTPUT`; POSIX: `unset REPOKIT_OUTPUT`).
- [ ] **Expected:** `[X] COMMIT BLOCKED` and no escape codes.
- [ ] **Why:** this is the answer for a console that cannot draw the symbols; `output = "plain"` in the settings does the same permanently.

### HV.4 -- A vendored change takes effect with no re-install
- [ ] **Steps:** open `proj/scripts/repokit-common/hooks/pre-commit`. Below the line `rk_setup_output`, add `echo "HELLO FROM THE VENDORED COPY"`. Then `python rk.py put ordinary`, `python rk.py commit docs/page.md`.
- [ ] **Expected:** the output includes `HELLO FROM THE VENDORED COPY`, with no installer run. Remove the line afterwards.
- [ ] **Why:** this is the reason the stubs exist; a subtree pull must update the hooks.

### HV.5 -- A branch without the copy: blocked when gated, warned otherwise
- [ ] **Steps:** `git -C proj checkout -q --orphan live`, `git -C proj rm -rq --cached .`, then delete `proj/scripts` (cmd: `rmdir /s /q proj\scripts`; PowerShell: `Remove-Item -Recurse -Force proj\scripts`; POSIX: `rm -rf proj/scripts`). Then `python rk.py put ordinary`, `git -C proj add -f docs/page.md`, and G-COMMIT. Next, `git -C proj checkout -q --orphan feature/docs` and G-COMMIT again.
- [ ] **Expected:** on `live`, "BLOCKED -- the pre-commit checks cannot run: this checkout has no repokit-common copy, and 'live' is a gated branch". On `feature/docs`, a warning, and the commit goes through.
- [ ] **Why:** a guard that cannot run must never pass silently.

## Section 1: Worktree

### 1.1 The stubs serve a worktree
- [ ] **Steps:** `python rk.py reset`, `python rk.py worktree`, `python rk.py put --wt cfg-private`, `python rk.py put --wt private-claude-md`, `python rk.py commit --wt CLAUDE.md`.
- [ ] **Expected:** `.git is a file: True`, and the commit is blocked.

## What the automated tests DO cover

| Area | Where |
|---|---|
| Stubs installed, run the real hooks, follow the vendored copy, pass arguments, preserve pre-push's refs | `tests/test_install_hooks.py` |
| Missing copy: gated blocks, ungated warns, one-run override, stamped list, no glob expansion | `tests/test_install_hooks.py` |
| Gated branches for failing tests and a runner that cannot start; output modes; nothing-to-push | `tests/test_pre_push_hook.py` |
| Private branch names; first commit on a new branch | `tests/test_pre_commit_hook.py` |

## What the automated tests DON'T cover

- How the symbols and colours render in real consoles and IDE git panels (HV.2, HV.3)
- A person reading the installer's summary (HV.1)
- Machines other than Windows with Git for Windows (a POSIX box would also check that the stub's executable bit matters)

## Reporting issues found

Note the item (e.g. "HV.2, cmd.exe"), copy the exact command and output, keep the scratch folder, and file an issue referencing this checklist and 0.3.1.

## Cleanup

Delete the scratch folder with `dz safedel <folder>` if available, otherwise:
- **cmd.exe:** `cd /d %TEMP%` then `rmdir /s /q rk-v031`
- **PowerShell:** `Set-Location $env:TEMP; Remove-Item -Recurse -Force rk-v031`
- **POSIX:** `rm -rf /tmp/rk-v031`

Also unset `REPOKIT_OUTPUT` if you set it in HV.3. Nothing outside the scratch folder was changed.
