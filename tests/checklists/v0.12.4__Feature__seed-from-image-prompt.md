# Human Test Checklist: Seed recovered from an image's prompt block on drag-in

**Target version:** v0.12.4
**Ships with commit:** TBD (fix: dragged-in images recover their own seed, #58)
**Companion automated tests:** 83 unit tests in `tests/unit/` (PromptSeed.test.js 24, SeedWidget.test.js 33, others unchanged); 10 live e2e tests (`seed-dragin.spec.js` 4, `seed-reload.spec.js` 5, `seed-metadata.spec.js` 1); smoke 5; mutation sweeps in `tests/mutation/v0.12.4__sweep__*.md`

## What this is

v0.12.3 made the recycle button and the random-mode readout work after a reload, but an image generated with 0.12.2 carries the *previous* run's seed in its workflow block, so dragging one in showed the wrong seed with confidence. v0.12.4 reads the seed from the image's prompt block instead, the value Python actually received, so every image ever generated by SmartResCalc gives back its own seed. This checklist covers the paths the live tests cannot: real drag-and-drop, File > Open, webp files, and installs with other custom nodes that wrap the same frontend method.

## Prerequisites

1. ComfyUI at `http://localhost:8188` serving this checkout's `web/`; hard-refresh (Ctrl+Shift+R) after installing.
2. Debug logging on, in the browser console, then hard-refresh:
   ```javascript
   localStorage.setItem('DEBUG_SMART_RES_CALC', 'true')
   ```
3. Two images:
   - **OLD**: any image generated with SmartResCalc 0.12.2 in random mode (for the maintainers' machine: any `output/d3/*.webp`, or `output/seed_probe/probe_00001_.png`). Its probe row shows `own=False`.
   - **NEW**: any image generated with 0.12.3 or later (`own=True`).
   Run the probe on both first and note each one's `prompt (sent)` value; that is the number every step below expects:
   ```
   python tests/one-offs/measure_seed_metadata.py "<path to OLD>" "<path to NEW>"
   ```
4. **State isolation:** use a spare workflow tab. Nothing here writes to ComfyUI settings or to your images.

**Reset between sections:** close the workflow tab that the image opened.

## High-Value Verification (~5 minutes)

### HV.1 — Real drag-and-drop of an OLD image shows its own seed

Validates: the `app.handleFile` hook on the DOM drop path (the live tests call the method directly).

- [ ] **Steps:** drag OLD from Explorer onto the ComfyUI canvas.
- [ ] **Expected:** the workflow opens in random mode (green tint, lit dice), the value box shows OLD's `prompt (sent)` seed dimmed, recycle is lit. Console shows `[Image Seeds] handleFile(<name>, type=...)`, `... N SmartResCalc seed(s) in the prompt block`, and `[configure] Node <id>: seed from image prompt <old> -> <new> (<name>)`.
- [ ] **Why this matters:** this is the bug: before, the readout showed the previous image's seed.

### HV.2 — File > Open on the same OLD image

Validates: the second entry into `handleFile` (the hidden file input).

- [ ] **Steps:** Workflow menu > Open (or the Open button), pick OLD.
- [ ] **Expected:** same as HV.1.

### HV.3 — A webp image (WAS Node Suite "Image Save")

Validates: the webp reader and the capitalised `Prompt` EXIF key. The live tests only load PNG; the decision logic is unit-tested.

- [ ] **Steps:** drag an OLD `.webp` onto the canvas.
- [ ] **Expected:** same as HV.1; the console's `metadata keys=` line lists `Prompt,Workflow` (capitalised) and `seeds=1` or more.

### HV.4 — A NEW image behaves exactly as in v0.12.3

- [ ] **Steps:** drag NEW onto the canvas.
- [ ] **Expected:** readout equals NEW's `prompt (sent)` seed; the `seed from image prompt` line shows the same number on both sides of the arrow (prompt and property agree).

### HV.5 — Loading a workflow JSON is unchanged

- [ ] **Steps:** save the workflow from HV.4 as JSON, close the tab, open the JSON.
- [ ] **Expected:** readout and recycle as in v0.12.3; console shows `hydrated lastSeed=...` and **no** `seed from image prompt` line.

### HV.6 — Two images in quick succession each show their own seed

- [ ] **Steps:** drag OLD, then within about three seconds drag NEW.
- [ ] **Expected:** the second workflow shows NEW's seed, not OLD's; exactly one `seed from image prompt` line per load.

## Section 1: Installs with other custom nodes (~3 min)

Other extensions also wrap `app.handleFile`; the hook re-checks four times in the first eight seconds after setup and wraps whatever is current.

- [ ] After a hard refresh, the console shows `[Image Seeds] Installed image drag-in seed hook on app.handleFile (attempt 0, wrapping handleFile)` and, if another extension wrapped it later, further lines like `(attempt 250, wrapping _handleFile)`.
- [ ] Any file the other extension handles specially (for example an image without a workflow) still behaves as before: our hook only reads metadata and forwards every argument.
- [ ] Wait more than ten seconds after the page loads, then drag OLD: still HV.1 behaviour (the re-check window is about installation order, not about when you drop).

## Section 2: Odd files (~2 min)

- [ ] Drag a PNG with no metadata (a screenshot): the frontend's normal "no workflow" handling; console `metadata keys=` line with `seeds=0`; no error.
- [ ] Drag a `.json` workflow file: console `no metadata reader for <name>`; the workflow loads as before.
- [ ] Drag an OLD image whose SmartResCalc node was bypassed at generation time (if you have one): the node hydrates from the property only, no `seed from image prompt` line, no error.

## What the automated tests DON'T cover

- The DOM drop event and the File > Open input (HV.1, HV.2); the tests call `app.handleFile` directly.
- webp files end to end (HV.3); only the reader-choice and key-fallback logic is unit-tested.
- Installs whose other extensions wrap `handleFile` differently from this machine's (Section 1).
- Whether the dimmed readout is what you expect to see for an old image (judgement).

## Reporting issues found

1. Note the section and step, and whether the image is OLD or NEW.
2. Paste the `[Image Seeds]` and `[configure]` console lines and the probe row for that image.
3. File an issue referencing this checklist and v0.12.4, with the ComfyUI frontend version (Settings > About).
