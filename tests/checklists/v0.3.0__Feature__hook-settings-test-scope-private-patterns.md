# Human Test Checklist: hook settings, pre-push test scope, private-patterns

**Target version:** 0.3.0
**Ships with commit:** TBD (v0.3.0: project settings for the hooks, honest pre-push test outcomes, private-patterns enforced, installer backups)
**Companion automated tests:** 113 in the suite; new or extended for this release: `tests/test_repokit_config.py` (17), `tests/test_pre_push_hook.py` (20), `tests/test_pre_commit_hook.py` (+18 cases), `tests/test_install_hooks.py` (4)

## What this is

v0.3.0 lets a project configure the hooks through `[tool.repokit-common]` (in `pyproject.toml`, or `.repokit-common.toml` for projects without one), makes pre-push report what pytest actually did, enforces the long-documented `private-patterns`, and makes `install-hooks.sh` keep any hook it replaces. The automated tests build throwaway repositories and drive the hooks through real `git commit` and `git push`. This checklist does what they do not: installs the vendored copy into a **fresh consumer project** the way a user would, runs every hook from there and from a worktree, and has a person look at the output in real consoles. About 25 minutes; the high-value pass is about 5.

## Prerequisites

1. Git for Windows (or any git with bash), Python 3.11+ on `PATH` as `python`, and pytest installed.
2. **Nothing here touches a real repository.** A helper script builds everything inside one scratch folder: a bare "remote", a fresh consumer project `proj/` with this checkout vendored at `scripts/repokit-common/`, and later a worktree and a parent project. Every git call it makes runs inside that folder, with signing off (`-c commit.gpgsign=false -c tag.gpgsign=false`, identity via `-c user.email=... -c user.name=...`) and `core.hooksPath` pinned to `proj/.git/hooks`. Do not change global git config. Do not run these steps in dazzlecmd, ComfyUI-Smart-Resolution-Calc or this checkout.
3. Build the scratch folder (pick your shell; use a new folder name each run):

   **cmd.exe**
   ```cmd
   set RK=C:\code\git-repokit-common
   python %RK%\tests\checklists\v0.3.0__scratch.py init %TEMP%\rk-v030
   cd /d %TEMP%\rk-v030
   ```
   **PowerShell**
   ```powershell
   $env:RK = "C:\code\git-repokit-common"
   python "$env:RK\tests\checklists\v0.3.0__scratch.py" init "$env:TEMP\rk-v030"
   Set-Location "$env:TEMP\rk-v030"
   ```
   **POSIX**
   ```bash
   export RK=/c/code/git-repokit-common        # or wherever the checkout lives
   python "$RK/tests/checklists/v0.3.0__scratch.py" init /tmp/rk-v030
   cd /tmp/rk-v030
   ```

   From here on, **every command is identical in all three shells**: `python rk.py ...` and `git -C proj ...`, run from the scratch folder. `python rk.py` with no arguments lists the commands and fixtures.

4. **Reset between sections:** `python rk.py reset` puts `proj/` back on the seed commit on `main` and removes every fixture file. Installed hooks stay installed.

**Known quirk (not a failure):** if git rejects a push before running the hook, the hook receives no refs and prints "Tag-only push -- skipping validation". `rk.py push` forces pushes to the scratch remote to avoid this; the message itself is on the follow-up list.

## High-Value Verification (~5 minutes)

If any of these fail, the release is broken; stop and report.

### HV.1 -- Installing into a fresh project keeps the old hook

Validates: the vendored `install-hooks.sh` works from `scripts/repokit-common/` and backs up a hook it replaces.

- [ ] **Steps:**
  1. `python rk.py install`
  2. `git -C proj rev-parse --git-path hooks` then list that folder (cmd `dir proj\.git\hooks`, PowerShell `Get-ChildItem proj\.git\hooks`, POSIX `ls proj/.git/hooks`)
- [ ] **Expected:** installer exit 0; the output says the existing pre-commit hook was saved as `pre-commit.backup-YYYYMMDD-HHMMSS`; the folder has `pre-commit`, `post-commit`, `pre-push` and that one backup, whose content is the project's own hook (`# the project's own pre-commit hook`).
- [ ] **Why this matters:** a consumer's own hook must never be lost to an upgrade.

### HV.2 -- A project pattern blocks its path, and only its path

Validates: `private-patterns` entries are literal prefixes from the repository root.

- [ ] **Steps:**
  1. `python rk.py put cfg-private`
  2. `python rk.py put private-prefix` then `python rk.py commit drafts/idea.md`
  3. `python rk.py put private-mid-path` then `python rk.py commit tools/x/drafts/a.md`
- [ ] **Expected:** step 2 prints `COMMIT BLOCKED - Private Content Protection` naming `drafts/idea.md`, commit exit 1; step 3 commits (exit 0).
- [ ] **Why this matters:** a pattern that silently fails leaks private files; one that matches mid-path blocks legitimate work (measured: 20 legitimate files in one consumer under a regex reading).

### HV.3 -- Failing tests block main and say how many

- [ ] **Steps:** `python rk.py reset`, `python rk.py put tests-fail`, `python rk.py commit tests/test_a.py`, `python rk.py push main`
- [ ] **Expected:** `scope: tests/ (one-offs/ and thinking/ excluded)`, `Some tests failed: 1 failed ...`, the assertion text `deliberate failure`, then `BLOCKED: Cannot push to main with failing tests`; push exit 1.
- [ ] **Why this matters:** the gate's one job, now with its scope and count visible.

### HV.4 -- test-command replaces pytest

- [ ] **Steps:** `python rk.py reset`, `python rk.py put cfg-test-command-fail`, `python rk.py put tests-pass`, `python rk.py commit check.py tests/test_a.py`, `python rk.py push main`
- [ ] **Expected:** `test-command: python check.py`, `test-command failed (exit 1)`, `script says no`, BLOCKED; no pytest summary line.
- [ ] **Why this matters:** projects whose tests are scripts (ComfyUI-Smart-Resolution-Calc) depend on this.

### HV.5 -- A project inside another project reads its own settings only

- [ ] **Steps:** `python rk.py reset`, then `python rk.py nested`
- [ ] **Expected:** `settings file found from inside the submodule: (none)`. The parent project `super/` has settings (`test-command = "echo PARENT-SETTINGS"`); `proj`, cloned into it as a submodule, has none and must not pick up the parent's.
- [ ] **Why this matters:** otherwise a node inside DazzleNodes would run DazzleNodes' tests on its own pushes.

### HV.6 -- A test runner that cannot start is not called "failing tests"

- [ ] **Steps:** `python rk.py reset`, `python rk.py branch experiment`, `python rk.py put conftest-broken`, `python rk.py commit tests/conftest.py tests/test_a.py`, `python rk.py push experiment`
- [ ] **Expected:** `BLOCKED: the test runner could not run (pytest exit N)`, pytest's own `conftest is broken` error, and `This is not a test failure`; no "Some tests failed". In 0.3.0 this blocks **every** branch, this one included; the next release returns it to blocking only the gated branches (see the follow-up issue). Record what you see.

## Section 1: Installer

### 1.1 Re-running is quiet
- [ ] **Steps:** `python rk.py install` a second time.
- [ ] **Expected:** `... hook already up to date` for all three; no new `.backup-` files.

### 1.2 MANUAL: the installer by hand
- [ ] **Steps:** in Git Bash, `cd` into `proj` and run `bash scripts/repokit-common/install-hooks.sh`; answer the prompt.
- [ ] **Expected:** the prompt reads sensibly; the closing summary lists the hooks. **Known:** the summary text still describes the old hooks ("Run tests") and does not mention settings, test scope or backups -- note anything else that reads wrong.

## Section 2: pre-commit and private-patterns (reset first)

`python rk.py reset` then `python rk.py put cfg-private` before each subsection unless stated.

### 2.1 Non-ASCII pattern
- [ ] `python rk.py put private-non-ascii`, `python rk.py commit brouillons-é/idée.md`
- [ ] **Expected:** blocked, naming the file (the name may show `?` in consoles that cannot render it).

### 2.2 A file-name prefix
- [ ] `python rk.py put private-claude-md`, `python rk.py commit CLAUDE.md`
- [ ] **Expected:** blocked (the entry `CLAUDE.md` is a prefix that matches the file itself).

### 2.3 Built-ins still apply
- [ ] `python rk.py put private-builtin`, `python rk.py commit private/notes.md`
- [ ] **Expected:** blocked, although `private/` is not in the project's list.

### 2.4 The allowlist still exempts
- [ ] `python rk.py put allowlist`, `python rk.py commit drafts/keep.md`
- [ ] **Expected:** commits (exit 0).

### 2.5 A broken settings file blocks, and says where
- [ ] `python rk.py reset`, `python rk.py put cfg-broken`, `python rk.py put ordinary`, `python rk.py commit docs/page.md`
- [ ] **Expected:** `COMMIT BLOCKED - the repokit-common settings could not be read`, plus `cannot read <path to .repokit-common.toml>` with the TOML parser's reason.

### 2.6 From a worktree
- [ ] `python rk.py reset`, `python rk.py worktree`, `python rk.py put --wt cfg-private`, `python rk.py put --wt private-claude-md`, `python rk.py commit --wt CLAUDE.md`
- [ ] **Expected:** `.git is a file: True` from the worktree step; the commit is blocked on branch `release`.

### 2.7 A private branch is not checked
- [ ] `python rk.py reset`, `python rk.py branch private`, `python rk.py put cfg-private`, `python rk.py put private-prefix`, `python rk.py commit drafts/idea.md`
- [ ] **Expected:** commits (exit 0).

## Section 4: Settings and tools

### 4.1 sync-versions.py still stamps through the new lookup
- [ ] `python rk.py reset`, `python rk.py put cfg-versioned`, `python rk.py commit pyproject.toml pkg/__init__.py pkg/_version.py`
- [ ] **Expected:** `Version updated for commit` (pre-commit) and `Version updated with commit hash` (post-commit); `proj/pkg/_version.py` now has a `__version__` like `0.1.0_main_2-YYYYMMDD-<hash>`.

### 4.2 MANUAL: a Python without a TOML parser warns instead of blocking
- [ ] **Steps** (simulates Python before 3.11 without `tomli`; identical in all shells):
  ```
  python -c "import sys, runpy; sys.modules['tomllib'] = None; sys.modules['tomli'] = None; sys.argv = ['x', '--get', 'private-patterns', '--start', 'proj']; runpy.run_path('proj/scripts/repokit-common/repokit_config.py', run_name='__main__')"
  ```
  after `python rk.py put cfg-private`.
- [ ] **Expected:** `repokit-common: warning: ... needs a TOML parser ...; the project's settings are skipped`, exit code 0, no traceback. On a real machine with an older Python, a commit shows the same warning and goes through.

## Section 5: MANUAL -- how the output looks

Run HV.3 and 2.1 once in each console you use and note what you see:

- [ ] **cmd.exe** (default code page; check with `chcp`)
- [ ] **PowerShell** (Windows PowerShell 5.1 and PowerShell 7 if both are used)
- [ ] **Windows Terminal / Git Bash**

**Expected today:** the hooks print emoji (`✓ ❌ ⚠ 🔍`) and ANSI colour codes. A console that cannot show them prints `?` or raw codes like `[0;32m`; the helper replaces what it cannot print rather than crashing. Nothing should crash or garble the file names in a way that hides which file was blocked. Plain markers for such consoles are on the follow-up list; note how bad it is in each console.

## Reporting issues found

1. Note the section and step (for example "3.4").
2. Copy the exact `rk.py` command and its full output.
3. Keep the scratch folder; it holds the exact state.
4. File an issue referencing this checklist and version 0.3.0.

## Cleanup

The scratch folder is self-contained. Delete it with `dz safedel <scratch folder>` if available (recoverable), otherwise:

- **cmd.exe:** `cd /d %TEMP%` then `rmdir /s /q rk-v030`
- **PowerShell:** `Set-Location $env:TEMP; Remove-Item -Recurse -Force rk-v030`
- **POSIX:** `cd /tmp && rm -rf rk-v030`

Nothing outside the scratch folder was changed: no global git config, no real repository, no hooks outside `proj/.git/hooks`.
