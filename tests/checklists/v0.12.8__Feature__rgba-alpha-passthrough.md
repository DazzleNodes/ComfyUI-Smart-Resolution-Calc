# Human Test Checklist: RGBA (alpha) pass-through

**Target version:** v0.12.8 (version not yet bumped; the entry sits under `[Unreleased]` in CHANGELOG.md)
**Ships with commit:** TBD
**Companion automated tests:** 25 tests in `tests/test_rgba_alpha.py`. The red-green audit is `tests/one-offs/redgreen_rgba_alpha.py`, which breaks each fix and each `fill_alpha` path one at a time and checks the suite goes red: 20/20 did. The live probe is `tests/one-offs/live_rgba_alpha_probe.py` (T1–T7, needs a running ComfyUI restarted on this code).

## What this is

This checklist verifies, by hand, that SmartResolutionCalc keeps an image's alpha channel. That covers three things:

- The alpha reaches an RGBA-capable VAE (Qwen Image 2.1) on both the img2img and img2noise paths.
- The pad transforms work on an RGBA image.
- The mask cutout works on an RGBA image.

The automated tests use stub VAEs and a nearest-neighbour resize. They can't show what the real Qwen 2.1 VAE does with the alpha, how the result looks after decoding, or whether the server picked up the new code.

## Prerequisites

1. ComfyUI at `C:\code\ComfyUI_experiment` with the Qwen Image 2.1 models (`qwen_image_2.1_vae_bf16`, `qwen_image_2.1_int8_convrot`, `qwen3vl_8b_int8_convrot`), plus any SDXL or Flux VAE as the RGB control.
2. The dev junction `custom_nodes\smart-resolution-calc` → `C:\code\smart-resolution-calc-repo\github`.
3. **A full ComfyUI server restart** after pulling these changes. Both `py/` files changed.
4. A transparent PNG, for example any PNG with a cut-out subject.

**Building an RGBA image in a graph:** LoadImage gives `IMAGE` and `MASK`. Wire both into **Join Image with Alpha** (`image` ← IMAGE, `alpha` ← MASK). Its output is the RGBA image to feed into SmartResCalc's `image`.

**Reading the alpha back:** after VAE Decode, use **Split Image with Alpha**. Its `MASK` output is 1 − alpha. Preview it with **Mask To Image** → Preview Image. Save the decoded image with core **Save Image** (PNG), then open it in an editor that shows transparency.

## High-Value Verification (~5 minutes)

### HV.1: img2img keeps alpha with the Qwen 2.1 VAE

Validates: the encode path passes all 4 channels to an RGBA VAE.

- [ ] **Steps:**
  1. Join Image with Alpha → SmartResCalc `image`. Set `vae` to the Qwen 2.1 VAE and image purpose to `img2img`.
  2. Connect SmartResCalc `latent` → VAE Decode (same VAE) → Save Image.
- [ ] **Expected:** the saved PNG is RGBA, and the subject's transparent background is still transparent (allow a faint 1/255 floor in the background, which is the VAE's own behaviour).
- [ ] **Why this matters:** before this fix the alpha was dropped here, so the background came back opaque.

### HV.2: RGB VAEs are unaffected

Validates: 3-channel VAEs still get 3 channels.

- [ ] **Steps:** repeat HV.1 with an SDXL or Flux VAE.
- [ ] **Expected:** no error. The output is RGB and looks the same as before the change.
- [ ] **Why this matters:** the fix must not break the common case.

### HV.3: scale/pad on an RGBA image

Validates: the pad canvas matches the image's channels.

- [ ] **Steps:** feed the RGBA image into SmartResCalc with an aspect ratio different from the image's, and image mode `transform (scale/pad)`. Preview the IMAGE output.
- [ ] **Expected:** no error in the console. The padded bars show the chosen fill. The subject's own transparent areas stay transparent, and the padded bars are opaque.
- [ ] **Why this matters:** before this fix this raised a shape-mismatch error.

### HV.4: mask cutout on an RGBA image

Validates: the composite accepts an RGB fill under an RGBA image.

- [ ] **Steps:** with the RGBA image connected, also connect a mask to SmartResCalc's `mask` input and use an img2img mode.
- [ ] **Expected:** the console says `Mask composite APPLIED`, not `WARNING: Mask composite failed`.
- [ ] **Why this matters:** this failure was silent apart from the warning. The cutout simply didn't happen.

## Section 1: img2noise

### 1.1 img2noise pattern with the Qwen 2.1 VAE

- [ ] **Steps:** image purpose `img2img + img2noise` (or `img2noise`), RGBA image connected, Qwen 2.1 VAE, a non-trivial fill_type (for example `noise` or a DazNoise fill).
- [ ] **Expected:** no error, and the run completes. The pattern is VAE-encoded with 4 channels; the debug log shows `img2noise: VAE-encoded pattern, shape=...` with 64 latent channels.

### 1.2 crop/pad on an RGBA image

- [ ] **Steps:** as HV.3, with image mode `transform (crop/pad)`.
- [ ] **Expected:** as HV.3.

## Section 2: Dazzle Options `fill_alpha`

### 2.1 The demo workflow (the user's acceptance test)

- [ ] **Steps:**
  1. Copy `docs/workflow/smartrescalc-rgba-demo.png` into ComfyUI's `input/` folder.
  2. Drag `docs/workflow/SmartResCalc-RGBA-Alpha-Demo.json` into ComfyUI and queue it.
  3. Open both PNGs in `output/SmartResCalc-RGBA-demo/` in an editor that shows transparency.
- [ ] **Expected:**
  - **`opaque-fill`:** opaque green bars above and below the ring. The ring's hole and surroundings stay transparent.
  - **`transparent-fill`:** the bars are transparent too, and the ring is unchanged.
- [ ] **Why this matters:** this is the acceptance test the feature was asked for. A transparent image stays transparent when padded with `fill_alpha = transparent`.

### 2.2 The default is unchanged

- [ ] **Steps:** open a workflow saved before this change that has a Dazzle Options node. Check that `norm_mode`, `whitening`, `cutoff_curve` and `phase_randomize` show their saved values, and that `fill_alpha` shows `opaque`.
- [ ] **Expected:** saved values are intact, and queuing gives the same output as before.

### 2.3 Mask fill with `transparent`

- [ ] **Steps:** RGBA image, a mask connected, and Dazzle Options `fill_alpha = transparent`.
- [ ] **Expected:** where the mask is 0, the output is transparent instead of showing the fill. Without Dazzle Options it shows the opaque fill, as before.

## What the automated tests DON'T cover

- The real Qwen 2.1 VAE's encode and decode, and what the alpha looks like afterwards.
- Whether the running server loaded the new code (restart semantics).
- DazNoise fills on CUDA under an RGBA image.
- How an older ComfyUI (< 0.6.0) behaves end to end. The tests only stub the missing `output_channels` attribute.
