# Human Test Checklist: Scale slider as a view on the native `scale` input

**Target version:** v0.12.7 (includes the unreleased v0.12.6 linked-scale fix)
**Ships with commit:** TBD (refactor: scale slider reads and writes the native `scale` widget)
**Companion automated tests:** `tests/e2e/widget-restore-frontend-153.spec.js` (7 live tests on frontend 1.53, none generating an image); unit 94; seed and smoke e2e unchanged. Red-green: all five reverted 0.12.7 behaviours caught.

## What this is

v0.12.5 kept two copies of the scale value (the hidden native `scale` widget and the custom slider) and patched the queued prompt to keep them agreeing; that patch overwrote a link into `scale` (fixed in 0.12.6). v0.12.7 removes the second copy: the slider is a view whose value is the native widget's, and the slider and MODE readout have their own names, so frontends no longer rename anything to `scale#1`. This checklist covers what the live tests cannot see: the slider's look and feel, a real scaled generation, and a real link.

## Prerequisites

1. ComfyUI with a 1.53.x frontend serving this checkout's `web/`; hard-refresh (Ctrl+Shift+R).
2. A model workflow that uses SmartResCalc's size, and a float node (for example `PrimitiveFloat`).
3. Step 1 generates one image; the rest only load, save and link.

---

## High-Value Verification (~5 minutes)

### HV.1 -- The slider scales the output

- [ ] **Steps:** base height 1400, drag the slider to 1.5x, queue once.
- [ ] **Expected:** output height 2096 (2100 rounded to divisible-by 16).
- [ ] **Why this matters:** on 1.53 before 0.12.5 the slider had no effect.

### HV.2 -- The slider value survives save and reload

- [ ] **Steps:** save the workflow, reload it (or drag in the HV.1 image).
- [ ] **Expected:** the slider shows 1.5x.
- [ ] **Why this matters:** the slider is no longer saved; its value comes from the native `scale` input.

### HV.3 -- A linked `scale` drives the output

- [ ] **Steps:** connect a float node (value 2.0) into SmartResCalc's `scale` input.
- [ ] **Expected:** the slider row reads "SCALE (linked)" and does not drag; a queued run uses 2.0. Disconnect: the slider comes back with its old value.
- [ ] **Why this matters:** 0.12.5 replaced a linked value with the slider's.

### HV.4 -- MODE readout and step sizes

- [ ] **Steps:** change dimensions or connect an image and watch the MODE line; open the slider's gear panel, change both step sizes, save and reload.
- [ ] **Expected:** MODE updates as before; step sizes persist.

---

## What the automated tests DON'T cover

- The slider's drawing, including the linked row, and real mouse drags (HV.1, HV.3).
- A real generation at a scale; the tests read the prompt payload.
- Older frontends (not installed on the test machine). Saved files keep the same shape, so no change is expected there.

## Cleanup

- Disconnect the float node; delete the HV.1 image if you do not want it.
