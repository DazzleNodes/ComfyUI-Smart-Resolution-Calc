# Human Test Checklist: generate-backlinks.py encoding detection

**Target version:** v0.2.10
**Ships with commit:** `v0.2.10: fix(generate-backlinks): detect note encoding instead of assuming UTF-8`
**Companion automated tests:** 12 tests in `tests/test_generate_backlinks.py` (9 anchors / 3 guards, red-green audited)

## What this is

`generate-backlinks.py` used to read every note as UTF-8 with `errors='ignore'`. That call never raises, so it looked safe — but a UTF-16 document decodes that way into `#\x00 \x00T\x00i…`, and every `[[wikilink]]` in it silently fails to match. The note reported zero links and vanished from the graph with no error at all.

This release detects the encoding instead, and reports any note that is not plain UTF-8 by name. The automated tests construct their fixtures with `write_bytes()` — which is exactly the thing this checklist exists to distrust. **The bug arrived through real Windows tools writing real files**, and the only way to know the fix meets them is to make those tools write the files.

Run this on **Windows**, in a real console, with `obsidiantools` installed.

## Prerequisites

1. **Windows** with PowerShell and `cmd.exe`, plus Git Bash or WSL for the POSIX forms.
2. **Python 3.10+** and `pip install obsidiantools` (Section 4 is skipped without it).
3. A scratch directory. Nothing here writes to a real vault except the **read-only** Section 5.

**Set up the scratch vault** (pick your shell):

**cmd.exe**:
```cmd
set VT=%TEMP%\gb-encoding-check
if exist "%VT%" rmdir /s /q "%VT%"
mkdir "%VT%\private\claude\_maps"
cd /d "%VT%\private\claude"
```

**PowerShell**:
```powershell
$env:VT = "$env:TEMP\gb-encoding-check"
if (Test-Path $env:VT) { Remove-Item -Recurse -Force $env:VT }
New-Item -ItemType Directory -Force "$env:VT\private\claude\_maps" | Out-Null
Set-Location "$env:VT\private\claude"
```

**POSIX**:
```bash
export VT=/tmp/gb-encoding-check
rm -rf "$VT"
mkdir -p "$VT/private/claude/_maps"
cd "$VT/private/claude"
```

**Reset between sections:** delete every `.md` in the vault except `TARGET.md`, and delete `_oracle/backlinks.md`. Re-run the setup block if in doubt — it is destructive only to the scratch path.

**Cleanup at the end:** see the Cleanup section. Nothing outside `%TEMP%` / `/tmp` is modified.

## High-Value Verification (~5 minutes)

If you only have five minutes, run these. They are the difference between "the fix works on fixtures" and "the fix works on files Windows actually produces."

### HV.1 — A note written by PowerShell redirection keeps its links

Validates: the single most common way a UTF-16 note enters a vault on Windows.

- [ ] **Steps** (PowerShell — the point is that *PowerShell* writes the file):
  ```powershell
  "# Target" > TARGET.md
  "# Source`n`nSee [[TARGET]] for the rest." > source.md
  python C:\code\git-repokit-common\generate-backlinks.py .
  ```
- [ ] **Expected:** output reports **1 note with backlinks, 1 link edge** — not 0. stderr carries a `Note: 1 file(s) are not UTF-8` block naming `source.md` (and `TARGET.md`).
- [ ] **Why this matters:** `>` in PowerShell 5.1 writes UTF-16LE with a BOM. This is the exact file that used to disappear from the graph in silence.

### HV.2 — The stderr report renders on a cp1252 console

Validates: the report is readable where it will actually be read.

- [ ] **Steps** (cmd.exe, default codepage — do NOT set `PYTHONIOENCODING`):
  ```cmd
  chcp
  python C:\code\git-repokit-common\generate-backlinks.py .
  ```
- [ ] **Expected:** `chcp` shows 437 or 1252. The encoding report prints legibly. **No `UnicodeEncodeError` traceback**, and no mojibake in the filenames.
- [ ] **Why this matters:** this tool has historically died on cp1252 consoles. A warning nobody can read is the same as no warning.

### HV.3 — Notepad "Save as Unicode" is caught too

Validates: the other common real-world source, written by a different tool.

- [ ] **Steps** (manual, no shell):
  1. Open Notepad, type `# Manual` then a new line, then `[[TARGET]]`
  2. File → Save As → set **Encoding: UTF-16 LE** → save as `manual.md` in the vault
  3. Re-run `generate-backlinks.py .`
- [ ] **Expected:** `manual.md` appears in the non-UTF-8 report **and** contributes its edge to `TARGET`.
- [ ] **Why this matters:** Notepad's BOM and line endings differ from PowerShell's. A fix tuned to one writer is not a fix.

### HV.4 — An ordinary Windows-1252 note is not mangled

Validates: the fallback's NUL-byte discriminator, which is the fix-within-the-fix.

- [ ] **Steps** (PowerShell):
  ```powershell
  [IO.File]::WriteAllText("$PWD\legacy.md", "# It's here`n`n[[TARGET]]`n", [Text.Encoding]::GetEncoding(1252))
  python C:\code\git-repokit-common\generate-backlinks.py .
  ```
  (Type a real curly apostrophe in `It's` — that is what makes the file invalid UTF-8.)
- [ ] **Expected:** `legacy.md` contributes its edge, and is reported as `cp1252` — **not** as `utf-16`.
- [ ] **Why this matters:** Python's UTF-16 decoder accepts any even-length input without a BOM. If the fallback tried it first, this file would decode to wide-character garbage and lose its links — the original bug, one level down.

### HV.5 — A clean vault stays quiet

Validates: the report does not cry wolf.

- [ ] **Steps:** delete every note from the sections above, write two plain UTF-8 notes that link to each other, re-run.
- [ ] **Expected:** edges reported correctly, and **stderr is empty**. No "Note: 0 file(s)…" line.
- [ ] **Why this matters:** a warning that always fires gets filtered out, and then the real one is invisible too.

### HV.6 — `--validate` says something useful about a vault it cannot check

Validates: the error-quality half of this release.

- [ ] **Steps:** put one UTF-16 note back in the vault, then run with `--validate`.
- [ ] **Expected:** a plain-language message saying cross-validation was skipped because the vault has non-UTF-8 files, naming them. **The words `UnboundLocalError` must not appear**, and the exit must be clean.
- [ ] **Why this matters:** the previous behaviour was a library-internal crash naming one of its own local variables — technically an error, practically no information.

## Section 1: Encodings by origin (~8 min)

### 1.1 UTF-16 BE, written by a tool rather than a fixture

- [ ] **Steps** (PowerShell):
  ```powershell
  [IO.File]::WriteAllText("$PWD\be.md", "# BE`n`n[[TARGET]]`n", [Text.Encoding]::BigEndianUnicode)
  python C:\code\git-repokit-common\generate-backlinks.py .
  ```
- [ ] **Expected:** edge present; `be.md` reported as `utf-16`.

### 1.2 UTF-8 with a BOM is NOT reported

- [ ] **Steps** (PowerShell):
  ```powershell
  [IO.File]::WriteAllText("$PWD\bom8.md", "# BOM8`n`n[[TARGET]]`n", [Text.UTF8Encoding]::new($true))
  python C:\code\git-repokit-common\generate-backlinks.py .
  ```
- [ ] **Expected:** edge present, and `bom8.md` **absent** from the report. A BOM alone is not a problem.
- [ ] **Check:** this is the noise-control case — most Windows-authored UTF-8 files carry a BOM, and flagging them all would make the report useless.

### 1.3 UTF-32

- [ ] **Steps** (PowerShell):
  ```powershell
  [IO.File]::WriteAllText("$PWD\wide32.md", "# W`n`n[[TARGET]]`n", [Text.UTF32Encoding]::new($false, $true))
  python C:\code\git-repokit-common\generate-backlinks.py .
  ```
- [ ] **Expected:** edge present, reported as `utf-32` (not `utf-16` — the UTF-32 LE BOM begins with the UTF-16 LE BOM, so the order of the BOM table decides this).

### 1.4 A file that is not text at all

- [ ] **Steps:** copy any small `.exe` or `.png` into the vault renamed to `binary.md`, re-run.
- [ ] **Expected:** a `Warning: N file(s) could not be decoded` block naming it; **every other note still indexed**. One bad file must not stop the walk.
- [ ] **Check:** exit code is still 0 and `_oracle/backlinks.md` was written.

## Section 2: The written index (~4 min)

### 2.1 The edge actually reaches the file on disk

- [ ] **Steps:** with a UTF-16 `source.md` present, run without flags, then read the output file.

  **cmd.exe**: `type _oracle\backlinks.md`
  **PowerShell**: `Get-Content _oracle\backlinks.md`
  **POSIX**: `cat _oracle/backlinks.md`
- [ ] **Expected:** a `## TARGET` section listing `source`. The console summary and the file agree.
- [ ] **Why:** the automated CLI test asserts this, but only on a fixture-written file.

### 2.2 `--dry-run` writes nothing but still reports encodings

- [ ] **Steps:** delete `_oracle/backlinks.md`, run with `--dry-run`.
- [ ] **Expected:** no `_oracle/backlinks.md` created; the encoding report still appears on stderr.

### 2.3 `--stats`, `--orphans`, `--broken` are unaffected

- [ ] **Steps:** run each flag in turn against the mixed-encoding vault.
- [ ] **Expected:** each behaves as before, and the UTF-16 notes participate in the counts rather than showing up as orphans.
- [ ] **Check:** a UTF-16 note that links to nothing and is linked from nothing should appear under `--orphans`; one that links to `TARGET` should not.

## Section 3: Real-vault scale (~5 min, READ-ONLY)

### 3.1 A multi-hundred-document vault is unchanged

- [ ] **Steps:** run `--dry-run` against a real vault of several hundred notes (for example a `private/claude/` directory in another project). **Use `--dry-run`** so nothing is written.
  ```
  python C:\code\git-repokit-common\generate-backlinks.py <path-to-real-vault> --dry-run
  ```
- [ ] **Expected:** the edge count matches what v0.2.9 produced for the same vault. The fix can only ever *add* edges; it must never remove one.
- [ ] **Check:** note the runtime. Reading bytes and decoding is marginally more work than `read_text`; on a 700-note vault it should still feel instant. If it does not, say so.
- [ ] **Note:** a script that automates this comparison across every vault on the machine is at `tests/one-offs/encoding_fix_vault_regression.py`.

### 3.2 A vault containing a `_links/` junction still terminates

- [ ] **Steps:** if you have a vault with `_links/` navigation junctions, run against it.
- [ ] **Expected:** completes; sibling vault notes are not indexed as local. (Regression guard for the v0.2.9 fix that shipped just before this one.)

## Section 4: `--validate` with obsidiantools installed (~4 min)

Skip this section if `pip show obsidiantools` finds nothing.

### 4.1 Clean vault — validation actually runs

- [ ] **Steps:** all-UTF-8 vault, `--validate`.
- [ ] **Expected:** `Running obsidiantools for cross-validation...` followed by an agreement count. No skip message.

### 4.2 Dirty vault — skipped with the real reason

- [ ] **Steps:** add one UTF-16 note, `--validate`.
- [ ] **Expected:** the skip message names the non-UTF-8 files and tells you to convert them. **No `UnboundLocalError`.** The backlinks index above it is still correct and still written.

### 4.3 Converting the file makes validation work again

- [ ] **Steps** (PowerShell):
  ```powershell
  $t = Get-Content -Raw -Encoding Unicode source.md
  [IO.File]::WriteAllText("$PWD\source.md", $t, [Text.UTF8Encoding]::new($false))
  python C:\code\git-repokit-common\generate-backlinks.py . --validate
  ```
- [ ] **Expected:** the skip message is gone, validation runs, and the edge from `source.md` is still present. The advice the tool gives is advice that works.

## Section 5: Known adjacent gap (verify, do not fix)

### 5.1 `vault-lint.py` still has the old defect

- [ ] **Steps:** run `python C:\code\git-repokit-common\vault-lint.py .` against the scratch vault while it contains a UTF-16 note with a deliberately broken wikilink (e.g. `[[NoSuchNote]]`).
- [ ] **Expected — and this is the *wrong* behaviour, recorded on purpose:** `vault-lint.py` does **not** report that broken link, because it reads notes with `errors="replace"` and cannot see into the file.
- [ ] **Check:** confirm it does not crash and does not rewrite the file.
- [ ] **Action:** note the result on issue #12. This is filed, not fixed, in v0.2.10 — folding it in would have doubled the diff and mixed two concerns in one commit.

Nine of these twelve fail if the fix is reverted (red-green audited). The other three are deliberate fences: the common UTF-8 path, the BOM-is-not-a-problem rule, and the report's silence on a clean vault.

## What the automated tests DON'T cover

- **Files written by real Windows tools.** Every fixture is built with `write_bytes()`. PowerShell `>`, Notepad's Save As, and .NET's encoders each produce their own BOM and line-ending combinations. This is the single biggest gap, and HV.1/HV.3/1.1–1.3 exist for it.
- **Console rendering.** Whether the stderr report survives codepage 437/1252 without a `UnicodeEncodeError`, and whether non-ASCII filenames render legibly. `capsys` sees none of this.
- **obsidiantools for real.** The `--validate` tests exercise the pre-check that *avoids* the library. Only a machine with it installed proves the happy path still agrees.
- **Scale and feel.** Byte-reading plus decoding versus a plain `read_text` across several hundred notes. Fixtures are three files.
- **Whether the advice works.** The report tells the user to convert the file to UTF-8; 4.3 is the only place anyone checks that doing so actually fixes it.
- **Junction-following on a real NTFS vault** with `_links/`.
- **Error-message quality.** Whether the wording helps someone who has never seen this bug, or merely fails to crash.

## Reporting issues found

1. Note the section and step number (e.g. "HV.4").
2. Capture the exact command and full output, including stderr.
3. Save the offending `.md` file — attach it, since the bytes are the whole story.
4. Record `chcp` output and `python --version`.
5. File an issue referencing this checklist and the v0.2.10 commit.
