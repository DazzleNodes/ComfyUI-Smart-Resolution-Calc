# Human Test Checklist: gh_issue_full.py shows issues in full by default

**Target version:** 0.2.12
**Ships with commit:** TBD (v0.2.12 feat(gh_issue_full): full by default)
**Companion automated tests:** 11 tests in `tests/test_gh_issue_full.py`; mutation sweep of 22 mutants in `tests/mutation/v0.2.12__sweep__gh-issue-full-default.md`

## What this is

`gh_issue_full.py` used to truncate an issue's body and comments unless `--full` was passed. It now prints in full by default, `--no-full` truncates, and the default can be changed per user (`GH_ISSUE_FULL_DEFAULT`) or per repo (`gh-issue-full-default` in `pyproject.toml`). The automated tests stub the network; this checklist runs the real script against a real GitHub issue and a real vendored layout. About 10 minutes.

## Prerequisites

1. `gh` CLI authenticated (`gh auth status`).
2. Any public issue with a long body or several comments. Examples use `djdarcy/EDAPITool` issue 9; substitute your own.
3. Make sure `GH_ISSUE_FULL_DEFAULT` is **unset** before each section:
   - cmd.exe: `set GH_ISSUE_FULL_DEFAULT=`
   - PowerShell: `Remove-Item Env:\GH_ISSUE_FULL_DEFAULT -ErrorAction SilentlyContinue`
   - POSIX: `unset GH_ISSUE_FULL_DEFAULT`
4. Run from the repokit-common checkout root unless a step says otherwise. Nothing here writes outside `%TEMP%` / `/tmp`.

## High-Value Verification (~5 minutes)

### HV.1 -- No flag prints in full

- [ ] **Steps** (same in every shell): `python gh_issue_full.py 9 --repo djdarcy/EDAPITool`
- [ ] **Expected:** the whole body and every comment; **no** line reading `Tip: use --full to see complete body and all comments`.
- [ ] **Why this matters:** this is the change. Forgetting a flag must not hide an issue's history.

### HV.2 -- `--no-full` truncates

- [ ] **Steps:** `python gh_issue_full.py 9 --repo djdarcy/EDAPITool --no-full`
- [ ] **Expected:** noticeably shorter output ending with the `Tip: use --full ...` line (for an issue long enough to truncate).
- [ ] **Why this matters:** the short view must stay one flag away.

### HV.3 -- The environment variable changes the default, and a flag beats it

- [ ] **Steps:**

  **cmd.exe**:
  ```cmd
  set GH_ISSUE_FULL_DEFAULT=truncated
  python gh_issue_full.py 9 --repo djdarcy/EDAPITool
  python gh_issue_full.py 9 --repo djdarcy/EDAPITool --full
  set GH_ISSUE_FULL_DEFAULT=
  ```
  **PowerShell**:
  ```powershell
  $env:GH_ISSUE_FULL_DEFAULT = "truncated"
  python gh_issue_full.py 9 --repo djdarcy/EDAPITool
  python gh_issue_full.py 9 --repo djdarcy/EDAPITool --full
  Remove-Item Env:\GH_ISSUE_FULL_DEFAULT
  ```
  **POSIX**:
  ```bash
  GH_ISSUE_FULL_DEFAULT=truncated python gh_issue_full.py 9 --repo djdarcy/EDAPITool
  GH_ISSUE_FULL_DEFAULT=truncated python gh_issue_full.py 9 --repo djdarcy/EDAPITool --full
  ```
- [ ] **Expected:** the first run is truncated (tip shown); the second is full (no tip).
- [ ] **Why this matters:** per-user preference works, and an explicit flag always wins.

### HV.4 -- Both flags together is refused

- [ ] **Steps:** `python gh_issue_full.py 9 --full --no-full`
- [ ] **Expected:** exit code 2 and `argument --no-full: not allowed with argument --full/-f`.
- [ ] **Why this matters:** a contradictory command is an error, not a silent pick.

## Section 1: The per-repo setting in a vendored layout

### 1.1 `pyproject.toml` sets the default

Build a throwaway consuming project with the script vendored at `scripts/repokit-common/`:

- [ ] **Steps:**

  **cmd.exe**:
  ```cmd
  mkdir %TEMP%\ghfull\scripts\repokit-common
  copy gh_issue_full.py %TEMP%\ghfull\scripts\repokit-common\
  (echo [tool.repokit-common]& echo gh-issue-full-default = "truncated") > %TEMP%\ghfull\pyproject.toml
  python %TEMP%\ghfull\scripts\repokit-common\gh_issue_full.py 9 --repo djdarcy/EDAPITool
  ```
  **PowerShell**:
  ```powershell
  New-Item -ItemType Directory -Force "$env:TEMP\ghfull\scripts\repokit-common" | Out-Null
  Copy-Item gh_issue_full.py "$env:TEMP\ghfull\scripts\repokit-common\"
  Set-Content "$env:TEMP\ghfull\pyproject.toml" "[tool.repokit-common]`ngh-issue-full-default = `"truncated`""
  python "$env:TEMP\ghfull\scripts\repokit-common\gh_issue_full.py" 9 --repo djdarcy/EDAPITool
  ```
  **POSIX**:
  ```bash
  mkdir -p /tmp/ghfull/scripts/repokit-common
  cp gh_issue_full.py /tmp/ghfull/scripts/repokit-common/
  printf '[tool.repokit-common]\ngh-issue-full-default = "truncated"\n' > /tmp/ghfull/pyproject.toml
  python /tmp/ghfull/scripts/repokit-common/gh_issue_full.py 9 --repo djdarcy/EDAPITool
  ```
- [ ] **Expected:** truncated output with the tip line -- the setting two directories above the script was found.

### 1.2 The environment variable beats the repo setting

- [ ] **Steps:** with the 1.1 project in place, set `GH_ISSUE_FULL_DEFAULT=full` (per Prerequisites syntax) and rerun the 1.1 command.
- [ ] **Expected:** full output, no tip. Unset the variable afterwards.

### 1.3 A typo is reported, not obeyed

- [ ] **Steps:** edit the 1.1 `pyproject.toml` value to `"sometimes"` and rerun.
- [ ] **Expected:** one line on stderr: `Warning: gh-issue-full-default in pyproject.toml is 'sometimes'; expected 'full' or 'truncated'. Ignoring it.` -- then full output. The warning reads clearly and is not repeated.

### 1.4 `--json` output stays clean with a bad setting

- [ ] **Steps:** with the typo still in place, add `--json` and pipe to `python -m json.tool`.
- [ ] **Expected:** valid JSON is pretty-printed; the warning appears on the terminal (stderr), not inside the JSON.

## Section 2: `--edit` still forces full

### 2.1

- [ ] **Steps:** `python gh_issue_full.py 9 --repo djdarcy/EDAPITool --no-full --edit 1`
- [ ] **Expected:** the original version of the body, in full, with no truncation tip.

## What the automated tests DON'T cover

- The real GitHub API and how long real issues render in full.
- Windows console rendering of the full body (codepage, emoji fallback with `--ascii`).
- Whether the warning text is clear to a person reading it.
- A real vendored checkout (the tests fake `__file__`; Section 1 uses a real copy).
