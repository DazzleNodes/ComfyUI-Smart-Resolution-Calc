# Human Test Checklist — vault-lint.py (v0.2.9)

**Scope**: first release of `vault-lint.py` — wikilink health checks, orphan/freshness/manifest reporting, and the safe-class `--fix` mode, per `docs/vault-spec.md` (wikilink rules + the fix contract in the write-authority section).

**Prerequisites**: Python 3.9+; a real vault to point at (any `private/claude/`); `generate-backlinks.py` present beside the tool (it is imported for the parser).

**Reset between sections**: work on a scratch COPY of a vault (`cp -r <vault> %TEMP%\vault-copy`); never `--fix` a real vault during testing.

## 1. Report mode (default, read-only)

- [ ] `python vault-lint.py <vault-copy>` prints: file count, broken links by class (`REL`, `MD`, `PIPE`, `TIMESTAMP`, `MISSING`, `ANCHOR`), unexpected orphans, expected-orphan archive counts, MOC freshness, manifest coverage
- [ ] Re-run `dir /T:W` (or `ls -l`) on a few vault files before/after: **no mtime changes** — report mode writes nothing
- [ ] Output renders cleanly in a plain `cmd.exe` console (non-ASCII paths/headings must not crash it — the cp1252 regression its sibling script had)

## 1b. Vault location

- [ ] Point the tool at a PROJECT root (the dir containing `private/`): it prints "descending to its vault" and reports the same numbers as pointing at the vault directly
- [ ] Point it at a directory with no vault anywhere under it: refused, exit code 2, reason on stderr
- [ ] `--dry-run` without `--fix` prints the note that it only affects `--fix`

## 2. Check mode (CI/hook shape)

- [ ] `--check` on a vault with findings: one summary line, exit code 1
- [ ] `--check` on a clean vault (or after fixing a small fixture): exit code 0
- [ ] Chainable: `python vault-lint.py <v> --check && echo CLEAN` behaves correctly both ways

## 3. Fix mode (the AUTH-3 contract)

- [ ] `--fix --dry-run` lists what WOULD change; files untouched (verify a listed file's bytes)
- [ ] `--fix` on the session-logger vault copy: **7 fixed, 5 refused** (3 prose refs, 2 timestamps) — the measured 2026-08-12 population
- [ ] Every fixed link resolves afterward: run `generate-backlinks.py --broken` on the copy — only the 5 refused remain
- [ ] Aliased link keeps its alias (`[[B.md|Bee]]` → `[[B|Bee]]`); table-pipe artifact becomes alias-free (`[[A\|x]]` → `[[A]]`) and the table still renders
- [ ] Content inside code fences is byte-identical after `--fix`
- [ ] Second `--fix` run: `Fixed: 0` (idempotent)
- [ ] Line endings survive `--fix`: on an LF-normalized file, `git diff` after a one-link fix shows ONE changed line, not every line (the CRLF-translation regression)
- [ ] Ambiguous target (two same-named files) is refused and the candidates are named in the refusal line

## 4. Judgment surface (what the tool must NOT do)

- [ ] Timestamps like `[[2026-05-06 14:58:40]]` are never rewritten
- [ ] Prose refs (`[[tool.repokit-common.extra-targets]]`) are never rewritten
- [ ] The tool never runs git, never touches files outside the given vault path

## What the mocks don't cover

- Real-console rendering of the class-tag table on cmd/PowerShell/Windows Terminal
- Whether the orphan report's expected/unexpected split matches *your* intuition on a mature vault (dazzlecmd: ~92 unexpected of 430+ — eyeball a sample; misclassifications here are spec-tuning input, not bugs)
- Whether refusal reasons read clearly enough to act on without opening the tool's source
