# Human Test Checklist: Seed recall after workflow reload and image drag-in

**Target version:** v0.12.3
**Ships with commit:** TBD (fix: seed recall after reload, image metadata carries its own seed)
**Companion automated tests:** 59 unit tests in `tests/unit/` (SeedWidget.test.js 33, DimensionWidget.test.js and WidgetValidation.test.js unchanged), 6 live e2e tests (`tests/e2e/seed-metadata.spec.js` 1, `tests/e2e/seed-reload.spec.js` 5), probe script `tests/one-offs/measure_seed_metadata.py`

## What this is

Verifies, in a real browser against a running ComfyUI, that a SmartResCalc node in random mode gives its seed back after the workflow is reloaded from JSON or an old output image is dragged in: the recycle button is lit immediately, the value box shows the seed, `-2`/`-3` continue from it, and the seed embedded in a newly generated image is the seed of that image (not the one before it). Run by whoever ships v0.12.3, and by anyone who suspects "my seed came back as -1" or "recycle gave me the wrong seed" later.

## Prerequisites

1. ComfyUI running at `http://localhost:8188` with this repo's `web/` being served (check: `custom_nodes/smart-resolution-calc` is this checkout, or the DazzleNodes aggregate points at it). Hard-refresh the browser tab after installing (Ctrl+Shift+R).
2. Debug logging on, so the seed messages appear in the browser console. In the browser console:
   ```javascript
   localStorage.setItem('DEBUG_SMART_RES_CALC', 'true')
   ```
   then hard-refresh. Turn it off afterwards with `localStorage.removeItem('DEBUG_SMART_RES_CALC')`.
3. A workflow with one SmartResCalc node whose seed widget is ON and in random mode (green tint, `Rnd: -1` or a dimmed number), wired to something that saves an image (SaveImage is enough; the node's own noise fill produces an IMAGE with no model). Save it as `seed-check.json` somewhere outside the repo.
4. Python 3.10+ for the probe script (no extra packages).
5. **State isolation:** work in a separate workflow tab; do not overwrite the workflow you were editing. Nothing here touches ComfyUI settings. The live e2e test writes `ComfyUI/output/seed_probe/probe_NNNNN_.png`; delete that folder afterwards if you like (see Cleanup).

**Reset between sections:** close the workflow tab and reopen `seed-check.json` (File > Open, or drag the JSON onto the canvas). That recreates the node objects, which is exactly the "reload" under test.

## High-Value Verification (~5 minutes)

**If you only have 5 minutes**, run these six. They are the user-visible promises of v0.12.3.

### HV.1 — Reload a JSON: recycle lit, seed visible, one click locks it

Validates: configure-time hydration of the recall buffer and the random-mode readout.

- [ ] **Steps:**
  1. Open `seed-check.json`, queue once, note the seed in the value box (dimmed number) and in the `info` output if wired to a display node.
  2. Save the workflow (Ctrl+S), close the tab, reopen the saved JSON.
- [ ] **Expected:** the value box shows the same number, dimmed, on the green tint; the dice button is lit; the recycle button is **not** greyed. Console shows `[configure] Node N: hydrated lastSeed=<seed> from properties`.
- [ ] **Then:** click recycle. The tint goes away, the number turns white, the dice button unlights. Queue once: the `info` output reports that seed.
- [ ] **Why this matters:** before v0.12.3 the box showed `Rnd: -1`, recycle was grey, and the first queue threw the seed away.

### HV.2 — Drag in an image generated after this fix: it shows its own seed

Validates: the seed embedded in image metadata is the seed of that image (A2), not the previous run's.

- [ ] **Steps:**
  1. With `seed-check.json` open and in random mode, queue **three** times so three images exist (call them A, B, C).
  2. Open a fresh workflow tab, drag image **C** from `ComfyUI/output/...` onto the canvas.
  3. Read the value box of the SmartResCalc node, then run the probe on C (any shell; the script expands the glob itself, so quote the path):
     ```
     python tests/one-offs/measure_seed_metadata.py "<path to image C>"
     ```
- [ ] **Expected:** the value box shows the seed the probe prints under `prompt (sent)` for that node; the probe's `own` column is `True`, `prev` is `False`.
- [ ] **Why this matters:** on pre-fix builds the embedded seed was always one run stale (7/7 measured), so "drag in C" recovered B's seed and looked like it worked.

### HV.3 — Drag in an image generated BEFORE this fix: documented previous-seed behaviour

Validates: the known limitation is exactly as documented and nothing crashes.

- [ ] **Steps:**
  1. Drag in any output image made before v0.12.3 (for the maintainers' machine: any `output/d3/*.webp`).
  2. Run the probe on it.
- [ ] **Expected:** node loads in random mode, value box shows a dimmed number equal to the probe's `prop dazzle_last` column, and the probe shows `own=False`, `prev=True` (or first-of-sequence). No console errors.
- [ ] **Why this matters:** users with older images should get a coherent, explained result, not a surprise.

### HV.4 — Random mode still re-rolls after a reload

Validates: hydration did not silently lock the seed.

- [ ] **Steps:**
  1. Reload `seed-check.json` (HV.1 state), do **not** click recycle, queue once.
- [ ] **Expected:** console shows `NORMAL resolved -1 -> <new seed>`; the value box now shows the **new** seed dimmed; recycle now recovers the new one (the buffer holds one seed back, same as within a session).
- [ ] **Why this matters:** "random" must mean random; the fix only makes the buffer available earlier.

### HV.5 — Fixed-mode workflow is unchanged

Validates: no regression for the common locked-seed case.

- [ ] **Steps:**
  1. In `seed-check.json`, click lock (new fixed random), save, close, reopen.
- [ ] **Expected:** value box shows the seed in white with no tint; dice unlit; recycle lit and recovers the seed that was current before the lock click.

### HV.6 — Increment mode continues from the saved seed after reload

Validates: `-2` reads the hydrated buffer.

- [ ] **Steps:**
  1. Reload `seed-check.json`, type `-2` into the value box, queue once.
- [ ] **Expected:** console shows `NORMAL resolved -2 -> <saved seed + 1>` and `info` reports saved seed + 1, not an unrelated random.

## Section 1: Rendering of the random-mode readout (~5 min)

### 1.1 Dimmed readout is legible on the green tint

- [ ] **Steps:** reload `seed-check.json`; look at the value box at 100% zoom and at 50% zoom.
- [ ] **Expected:** digits in green-grey (`#9bb59b`) on the dark green tint are readable at both zooms; they are visibly *not* the same white as a fixed seed.
- [ ] **Check:** the `-` and `+` buttons and the three icon buttons are unchanged.

### 1.2 A 16-digit seed fits the box

- [ ] **Steps:** in the value box, type `1125899906842623` (16 digits), click lock to leave fixed mode, click dice (back to random; the typed value becomes the recall buffer via the lock click), reload.
- [ ] **Expected:** all 16 digits render inside the box with no clipping into the `+` button. If they clip, note the browser and zoom; the budget is 116 px at 12 px monospace.

### 1.3 Edit prompt shows the stored value, readout shows the seed

- [ ] **Steps:** in random mode with a readout showing, click the number to edit.
- [ ] **Expected:** the prompt opens with `-1` (the stored value). Cancel: nothing changes. Type a number: the box shows it in white and random mode ends.

### 1.4 Toggle OFF shows the literal

- [ ] **Steps:** with a readout showing, click the SEED toggle off.
- [ ] **Expected:** grey `Rnd: -1`, no readout, no tint. Toggle back on: readout returns.

### 1.5 `-2` / `-3` keep their labels

- [ ] **Steps:** type `-2`, then `-3`.
- [ ] **Expected:** `Inc: -2` and `Dec: -3` in white, no readout, even though a last seed is known.

## Section 2: DazzleCommand interplay (~5 min, skip if you do not use DazzleCommand)

### 2.1 'reuse last seed' after a reload

- [ ] **Steps:** connect a DazzleCommand to the node, set it to Play with `reuse last seed`, queue once, save, reload, queue again.
- [ ] **Expected:** console `REUSE LAST -> <seed>` with the seed from before the reload; downstream nodes cache (second queue is fast). Behaviour identical to v0.12.2; hydration just happens earlier.

### 2.2 Recycle counts as user intent once

- [ ] **Steps:** same setup; reload, click recycle, queue.
- [ ] **Expected:** console `REUSE LAST overridden by user seed intent`, the widget's locked seed is used, then the next queue re-locks on it.

## Section 3: Tab switch, copy, paste (~3 min)

### 3.1 Tab switch before any queue

- [ ] **Steps:** open `seed-check.json` in tab A, open another workflow in tab B, switch back to A.
- [ ] **Expected:** readout and recycle state in A are intact (node objects were recreated; hydration ran again).

### 3.2 Copy and paste a node

- [ ] **Steps:** Ctrl+C / Ctrl+V the SmartResCalc node.
- [ ] **Expected:** the copy shows the same readout and its recycle recovers the same seed (the property travels with the copy). This is intended.

## Section 4: Console messages (~2 min)

- [ ] After a reload: exactly one `[configure] Node N: hydrated lastSeed=...` per SmartResCalc node with a saved seed; none for nodes saved before v0.12.2.
- [ ] After a queue: `[Seed Intercept] Node N: workflow snapshot dazzle_last_seed <old> -> <new>` for every node with seed ON. If you ever see `workflow snapshot node not found`, file an issue with the frontend version: image metadata will be one run stale again.
- [ ] No `TypeError` or `ReferenceError` mentioning SmartResCalc, SeedWidget, or DazzleToggleWidget.

## What the automated tests DON'T cover

- How the dimmed readout actually looks on the tint, at different zooms and on a light theme (1.1)
- Whether 16 digits fit the 116 px value box in a real canvas font (1.2); the unit test only checks the character count
- The edit-prompt-shows-`-1`-while-box-shows-seed asymmetry as a UX judgement (1.3)
- Drag-and-drop of real output files, and `.webp` from WAS Node Suite specifically (HV.2, HV.3); the e2e test uses SaveImage PNGs
- DazzleCommand orchestration end to end with a real sampler (Section 2)
- Multiple workflow tabs and clipboard paste (Section 3)
- Any frontend build where node ids are numbers on both sides; the loose match handles both, but only the string/number case was observed live

## Reporting issues found

1. Note the section and step number.
2. Capture the exact console lines (`[configure]`, `[Seed Intercept]`) and a screenshot of the widget.
3. Run the probe on the image involved and paste its row.
4. File an issue referencing this checklist and v0.12.3; mention the ComfyUI frontend version (Settings > About).

## Cleanup

- Turn debug logging off: `localStorage.removeItem('DEBUG_SMART_RES_CALC')` in the browser console, then hard-refresh.
- Optional: remove the e2e test's outputs. Prefer `dz safedel` where installed; otherwise:

  **cmd.exe**:
  ```cmd
  rmdir /s /q "C:\code\ComfyUI_experiment\output\seed_probe"
  rmdir /s /q tests\one-offs\tmp
  ```
  **PowerShell**:
  ```powershell
  Remove-Item -Recurse -Force "C:\code\ComfyUI_experiment\output\seed_probe"
  Remove-Item -Recurse -Force tests\one-offs\tmp
  ```
  **POSIX**:
  ```bash
  rm -rf "$COMFYUI_DIR/output/seed_probe" tests/one-offs/tmp
  ```
  (adjust the ComfyUI path to your install; `tests/one-offs/tmp/` is gitignored.)
