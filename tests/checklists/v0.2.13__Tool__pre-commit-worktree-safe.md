# Human Test Checklist: pre-commit checks work in git worktrees

**Target version:** 0.2.13
**Ships with commit:** TBD (v0.2.13 fix(hooks): pre-commit checks work in git worktrees; show why a version stamp failed)
**Companion automated tests:** 6 tests in `tests/test_pre_commit_hook.py` (red-green: 4 anchors, 2 fences); suite 54

## What this is

`hooks/pre-commit` kept its staged-file list under `$REPO_ROOT/.git/`, which is a file in a git worktree, so its private-content and large-file checks passed every commit made from a worktree (#9). It now keeps the list in the checkout's own git directory and refuses to commit if the list cannot be written. A failed version stamp now prints the tool's output. The automated tests build throwaway repositories; this checklist runs the hook as a real consumer installs it, in real Git Bash, from a clone and from a worktree. About 10 minutes.

## Prerequisites

1. Git for Windows (Git Bash) or any POSIX git, and Python on `PATH`.
2. A scratch folder, never a real project. Every git command below carries `-C <scratch>`, and every commit carries `-c user.email=t@example.invalid -c user.name=t -c commit.gpgsign=false`, so nothing lands in a real repository and no signing prompt appears. Do not change global git config.
3. Set the scratch path and this checkout's path once (pick your shell):

   **cmd.exe**
   ```cmd
   set RK=C:\code\git-repokit-common
   set SC=%TEMP%\rk-hooktest
   mkdir %SC%
   ```
   **PowerShell**
   ```powershell
   $env:RK = "C:\code\git-repokit-common"
   $env:SC = "$env:TEMP\rk-hooktest"
   New-Item -ItemType Directory -Force $env:SC | Out-Null
   ```
   **POSIX**
   ```bash
   export RK=/c/code/git-repokit-common
   export SC=/tmp/rk-hooktest
   mkdir -p "$SC"
   ```

4. Build a repository and a worktree of it, and install the hook with the real installer (commands shown in POSIX; in cmd use `%SC%`/`%RK%`, in PowerShell `$env:SC`/`$env:RK`):
   ```bash
   git init -q -b main "$SC/repo"
   git -C "$SC/repo" -c user.email=t@example.invalid -c user.name=t -c commit.gpgsign=false commit -q --allow-empty -m seed
   (cd "$SC/repo" && printf 'y\ny\ny\n' | sh "$RK/install-hooks.sh")
   git -C "$SC/repo" worktree add -q -b release "$SC/wt"
   ```
   `install-hooks.sh` asks before overwriting; the piped `y` answers it. Confirm `$SC/wt/.git` is a file (`type`, `Get-Content` or `cat` shows `gitdir: ...`).

**Reset between sections:** `git -C <repo or wt> reset -q` to unstage, then delete the files you created.

## High-Value Verification (~5 minutes)

### HV.1 -- A private file is blocked from the worktree

- [ ] **Steps:** create `$SC/wt/private/notes.md`, then
  `git -C "$SC/wt" add -f private/notes.md` and
  `git -C "$SC/wt" -c user.email=t@example.invalid -c user.name=t -c commit.gpgsign=false commit -m try`
- [ ] **Expected:** `COMMIT BLOCKED - Private Content Protection`, the file listed, non-zero exit, no new commit (`git -C "$SC/wt" log --oneline -1` unchanged).
- [ ] **Why this matters:** this is #9. Before 0.2.13 this commit went through with no message.

### HV.2 -- An ordinary commit from the worktree goes through

- [ ] **Steps:** reset, create `$SC/wt/src/a.py`, add and commit it the same way.
- [ ] **Expected:** the commit is made; the hook prints `Pre-Commit Check` and `Branch: release (public)`; no `Not a directory` anywhere.
- [ ] **Why this matters:** failing closed must never block normal work.

### HV.3 -- The clone behaves as before

- [ ] **Steps:** repeat HV.1 and HV.2 in `$SC/repo`.
- [ ] **Expected:** private file blocked; ordinary file committed.
- [ ] **Why this matters:** the fix must not change normal checkouts.

### HV.4 -- A consumer that vendors repokit-common as a subtree

- [ ] **Steps:** in a scratch copy (or a worktree) of a consuming project that has `scripts/repokit-common`, install the hooks from `scripts/repokit-common/install-hooks.sh`, then repeat HV.1 and HV.2 there.
- [ ] **Expected:** as above, and the ordinary commit includes the stamped version file (`git show --stat HEAD` lists it). The hook prints `Version updated for commit` only when the file is named `_version.py`; a root `version.py` is stamped without that line.
- [ ] **Why this matters:** consumers get the hook through the subtree, not from this checkout.

### HV.5 -- A failed version stamp says why

- [ ] **Steps:** in `$SC/repo`, create `scripts/sync-versions.py` containing `import sys; print('stamp failed on purpose'); sys.exit(1)`, add it, and commit anything.
- [ ] **Expected:** the commit is made; `Warning: Version update failed but continuing:` followed by the indented line `stamp failed on purpose`.
- [ ] **Why this matters:** a hidden failure once let a commit ship with a stale version string.

## What the automated tests DO cover

| Area | Test file | Count |
|---|---|---|
| Private file and >10 MB file blocked from a worktree; private file blocked from a clone; ordinary worktree commit allowed; fail closed when the staged list cannot be written; version failure shows the tool output | `tests/test_pre_commit_hook.py` | 6 |

## What the automated tests DON'T cover

- Git for Windows' real `sh` running an installed hook (the tests invoke it through `git commit`, but with `core.hooksPath` pinned to a temp directory, not via `install-hooks.sh`).
- The installer's overwrite prompt and a consumer's subtree layout (HV.4).
- Whether the messages read clearly in a real terminal, emoji included, on the Windows console.
- The fail-closed message in a real failure (the test forces it with a stand-in `git`); if you ever see it for real, capture how.

## Reporting issues found

1. Note the HV step, your shell, and `git --version`.
2. Paste the full hook output.
3. File an issue referencing this checklist, v0.2.13 and #9.

## Cleanup

Remove the worktree first, then the scratch folder:
```bash
git -C "$SC/repo" worktree remove --force "$SC/wt"
```
then delete `$SC` with `dz safedel -r "$SC"` if available, otherwise `rmdir /s /q %SC%` (cmd), `Remove-Item -Recurse -Force $env:SC` (PowerShell) or `rm -rf "$SC"` (POSIX). Unset `RK` and `SC` as in the prerequisites.
